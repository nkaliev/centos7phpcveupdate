# Обновление PHP на CentOS 7

Обновляй установленную ветку PHP 8.2, 8.3, 8.4 или 8.5. Переход между ветками выполняй только по отдельному запросу. Сохраняй версии PECL и остального ПО; меняй их лишь при необходимости для совместимости или зависимостей PHP.

## Определение окружения

- Проверь ОС, архитектуру, свободное место, установленные RPM и активные репозитории. Определи владельца PHP через `rpm -qf`, версии и происхождение пакетов через NAME, VERSION, RELEASE, ARCH и SOURCERPM.
- Различай системные RPM, параллельные установки, контейнеры и PHP из исходников. Описанный ниже путь подходит для совместимой RPM-установки; не заменяй другие варианты системными пакетами автоматически.
- Определи используемый SAPI: Apache/mod_php, PHP-FPM, CGI, CLI и длительно работающие процессы. Путь и версия CLI могут отличаться от веб-PHP.
- Зафиксируй исходные модули, предупреждения, конфигурацию и ответы приложения. Не исправляй посторонние локальные настройки в рамках обновления.

## Исправленная версия и источник

Сверь [поддерживаемые ветки PHP](https://www.php.net/supported-versions.php), объявление исправления и доступные EL7-сборки. Доступный старый патч не обязательно исправляет нужную уязвимость. Для backport проверяй полный RPM release и сведения поставщика.

Remi закрыл [репозитории EL7](https://rpms.remirepo.net/enterprise/7/). Кандидат для совместимых установок — [RocketSky](https://yum.rocketsky.ch/). На 24 октября 2026 года он публикует 8.2.35, 8.3.36, 8.4.27 и 8.5.12. Это ориентиры на указанную дату, не постоянные цели обновления: сверяй актуальный индекс перед установкой.

Адреса RocketSky:

- Release-RPM: `https://yum.rocketsky.ch/rocketsky-php-release.rpm`
- Индекс: `https://yum.rocketsky.ch/php/PACKAGE-INDEX.json`
- Репозиторий: `https://yum.rocketsky.ch/php/el/7/phpXY/x86_64/`, где XY — 82, 83, 84 или 85.
- Общие зависимости: `https://yum.rocketsky.ch/php/el/7/common/x86_64/`
- Инструкция: `https://yum.rocketsky.ch/php/docs/INSTALLATION-X.Y.md`
- Ограничения: `https://yum.rocketsky.ch/php/docs/KNOWN-LIMITATIONS-X.Y.md`
- Ключ: `https://yum.rocketsky.ch/php/keys/RPM-GPG-KEY-rocketsky-php`

Наблюдавшийся отпечаток ключа: `1446 C761 62B6 9F84 010B 4416 BA4A C5F8 4593 6FD0`. Получение ключа с сайта поставщика не является независимым подтверждением доверия. Проверяй смену ключа, подписи RPM и подпись `repodata/repomd.xml.asc`. Сверяй контрольные суммы пакетов именно с проверенными метаданными. Сохраняй `gpgcheck=1`, `repo_gpgcheck=1`, `sslverify=1`; оригинальные RPM других поставщиков проверяй их ключами.

До установки release-RPM изучи его файлы, зависимости и scriptlets через `rpm -qp`. Управляющие скрипты сначала читай: они могут менять выбор репозитория и устанавливать плагин YUM. Не подключай EL8/EL9 RPM к EL7. Если совместимой исправленной сборки нет, сообщи об этом; не меняй ветку и не переходи к сборке из исходников без согласования задачи.

## Подготовка и установка

1. Сохрани список RPM с версиями, конфигурацию PHP, соответствующих служб и репозиториев. Подготовь старые RPM для отката либо доступный восстанавливаемый снимок. Архив настроек и RPM не равнозначен снимку всей системы.
2. Выбери только уже установленные основные пакеты PHP нужной ветки. Проверяй SOURCERPM и зависимости: версии PECL имеют собственную нумерацию. Не добавляй отсутствующие расширения.
3. Рассчитай зависимости без установки. Сопоставь PHP API/Zend ABI кандидатов с требованиями расширений. Новую библиотеку добавляй только по фактической необходимости; не закрепляй заранее число пакетов или список зависимостей.
4. Подготовь отдельный каталог с точным набором новых и необходимых дополнительных RPM. Проверь суммы и подписи. При медленной загрузке допустимо скачать RPM другим маршрутом и передать серверу с повторной проверкой.
5. Проверь отсутствие конкурирующей транзакции YUM/RPM. Не удаляй блокировку и не прерывай чужую команду без разрешения. При блокировке останови свою ожидающую команду и выясни состояние другой операции.
6. Выполни тест транзакции. Не обходи несовместимость через `--nodeps`, `--skip-broken` или принудительное удаление зависимостей.
7. В пределах полученного разрешения установи проверенные ключи и настройки источника при необходимости, затем выбранные RPM с журналом. После ошибки выясни фактическое состояние пакетов перед повтором или откатом.

Для ограничения состава изменений используй локальные подписанные RPM и отключённые внешние репозитории. Проверь содержимое каталогов и итоговую транзакцию перед выполнением:

```bash
# Обновление установленных пакетов:
yum --disablerepo='*' --setopt=localpkg_gpgcheck=1 localupdate /ABSOLUTE/STAGE/new/*.rpm

# Если нужны также новые зависимости:
yum --disablerepo='*' --setopt=localpkg_gpgcheck=1 localinstall /ABSOLUTE/STAGE/new/*.rpm /ABSOLUTE/STAGE/deps/*.rpm
```

Не запускай общий `yum update` или обновление по маске `php*`. Не отключай общий репозиторий постоянно без причины: он может требоваться будущим зависимостям. При локальной транзакции достаточно заранее скачать нужные пакеты.

## Применение и проверка

- Проверь CLI-версию, stderr запуска, модули и сохранность конфигурации. `.rpmnew` — шаблон для сравнения, а не готовая замена настроек.
- Для Apache/mod_php проверь `httpd -t` и перезапусти Apache. Для PHP-FPM проверь конфигурацию нужного экземпляра и перезапусти его. Заранее прочитай scriptlets старых и новых RPM: обновление может автоматически перезапустить службу. Примени обновление к затронутым длительно работающим PHP-процессам.
- Подтверди версию через SAPI приложения. Временную веб-пробу ограничивай локальным доступом, выводи только нужные результаты и удаляй в `finally`.
- Проверь используемые расширения и функции приложения. Для БД подходит безопасный `SELECT 1`; наличие класса драйвера не подтверждает соединение. HTTP 200 не заменяет функциональную проверку.
- Читай ограничения выбранной сборки. RocketSky документирует унаследованные дефекты внешней GD, включая падение в определённом тесте вращения: проверяй используемые приложением операции.
- Сравни полный список RPM до/после: должны измениться только выбранные PHP-пакеты, необходимые зависимости и явно добавленные ключи/настройки репозитория.
- При регрессии исправь совместимость в пределах задачи либо восстанови подготовленный набор пакетов и нужную конфигурацию, затем повторно примени и проверь соответствующую службу.

В результате укажи версии до/после, изменённые зависимости, перезапуски, выполненные проверки и их пределы, расположение материалов отката.
